## Problem

- Today: SpeakMore 0.6.2 的界面使用 Electron，业务使用 Node；原生助手依赖 Swift/AppKit，安装、权限引导、控制通道和发布链包含 macOS/Unix 假设。Windows 用户尚无可用安装包。
- Impact: 用户无法在 Windows 11 延续现有听写、历史和模型设置体验；开发者需要在 WSL2 中编写代码，同时验证真实 Windows 应用中的输入行为。
- Evidence: [平台声明](../../package.json#L26)、[原生助手](../../native/main.swift#L25)、[助手通信](../../src/app/helper.mjs#L15)、[助手启动](../../src/app/main.mjs#L354)、[控制通道](../../src/control.mjs#L104)、[数据路径](../../src/storage/paths.mjs#L21)、[打包](../../scripts/build/mac-app.mjs#L22)、[发布布局](../../scripts/release/release-layout.mjs#L14)。[逆向目标](../../targets/typeless/README.md#L3)是 macOS Typeless，其 Windows 代码分支不能证明 Windows 原生能力已经实现或验证。

## Goal

- Goal: 首先在本机 Windows 11 跑通真实热键听写、整理与前台输入框投递，再验证本地 .exe 安装使用；保留当前 SpeakMore 功能迁移目标，以 WSL2 为主要编码环境，能复现 Windows 调试与构建。
- Target Platforms: Windows 11 x64 Desktop；macOS 12+ Desktop（既有平台回归）。
- In Scope:
  - 热键听写、取消与完成、文字投递、录音与历史、模型与 key、用量统计、设置、主题、国际化、首次引导、托盘、开机启动、CLI、安装升级与卸载。
  - Windows 系统适配、本地调试与 .exe 安装验证，以及 WSL2 开发环境准备说明。发布相关功能按 R11 分阶段交付。
- Out of Scope:
  - Linux 用户发行版、翻译、问任何事、个人词典、屏幕上下文采集、云同步和全新视觉设计。
  - 跨 macOS/Windows 自动迁移用户历史与加密 key；把现有 UI 整体重写成 WinUI/WPF。
  - Windows ARM64 兼容；当前迭代的公开分发、Windows 代码签名、COS/CDN 接入及远端更新链路。

## Rules

- R1: 功能基线为 Source 提交的 README、代码与测试共同描述的 SpeakMore，而非 Typeless 全量功能。macOS 现有数据、热键选项和发行入口保持兼容。Windows 的按键、系统权限文案和窗口控制使用对应平台语义；平台限制必须明确列出，不能以删掉功能冒充迁移完成。
- R2: 共用 Electron/Node 业务与 HTML/CSS/JavaScript 页面、主题 token。Windows 增加 C++/Win32 助手，沿用现有 JSON 行协议的事件和命令边界；只有协议确实无法表达平台能力或失败原因时才扩展。状态中区分能力、适用性、可用性和失败，不能把 macOS 的 trusted 权限字段直接伪装成 Windows 已授权。
- R3: Windows 默认键确定为 Right Ctrl：单击开始，松开后持续录音，再次按下结束并整理投递，不需一直按住。其余沿用现有 macOS 状态机的组合键误触防护、取消、完成、录音上限、静音检测、初始化与失败语义；包括按住超过现有 LONG_PRESS_MS 的取消行为，不新增按住说话模式。不承诺普通系统 API 无法观察的 Fn，不破坏 AltGr、其他修饰键组合或造成卡键；这些行为纳入 A2 验证。
- R4: 悬浮条保持当前主屏幕定位范围，不抢走输入框焦点。Esc 和按钮鼠标拦截仅在适用会话中生效；完成、取消、超时、父进程退出或页面崩溃后释放。坐标换算覆盖 Windows DPI、主屏切换和任务栏工作区域，保留非录音事件的正常传递。
- R5: 结果按现有语义先保存录音与历史，再投递；失败的听写仍可查录音和原因。成品以 Unicode 纯文本经剪贴板与 Ctrl+V 投递，不注入富文本。原剪贴板为空，或包含可完整快照的普通文本、图片、文件列表、HTML/RTF 时，自动投递后恢复原内容及支持的格式；此处文件列表不包括虚拟文件或文件内容传输。存在无法完整快照的私有格式、延迟呈现、OLE/虚拟文件对象时，不覆盖原剪贴板，提示从历史手动复制。超时或可检测的投递失败，只有本次仍持有剪贴板且原内容可安全处理时才留存结果供手动粘贴；用户期间新复制的内容始终优先，不能被恢复旧内容或失败兜底覆盖，此时结果从历史取回。快照/恢复失败必须显式报告；模拟输入已发送不等于目标已接收，不承诺通用的插入成功确认。
- R6: 默认按 Windows 标准用户权限运行。管理员窗口、UAC 安全桌面、密码输入、禁止粘贴或其他受限目标不承诺自动注入，不采用全程提权绕过边界。可检测失败或助手异常时保留历史与可恢复文字，提供手动粘贴提示；无法可靠检测接收的目标也可以从历史取回结果。
- R7: 保留 Gemini/OpenAI、现有模型与思考设置、提示词、缓存、重试和计费流程，key 由用户提供。通过 Electron safeStorage 使用 Windows 系统保护能力，禁止明文降级；不承诺密文可跨操作系统、用户或机器解密。日志不含 key、录音内容和结果正文，不新增上下文采集或遥测。服务错误映射到本地化状态，普通界面不直接展示原始响应体、内部错误码或异常字符串。
- R8: 保留现有设置、数据库、录音和用量语义；Windows 默认用户数据目录为本地应用数据目录下的 SpeakMore，并保留 SPEAKMORE_HOME。程序与用户数据可分离更新，访问控制采用 Windows 权限机制，不把 chmod 当成 ACL。避免为平台迁移改变数据库 schema；若确需不兼容变更，先补迁移、备份及回滚规则。
- R9: Windows GUI 与 Windows CLI 共享同一用户和同一数据目录的控制端点、单实例与超时语义，控制通道使用命名管道并提供经验证的访问控制或等效认证。端点命名不等于授权。停止、重启和升级只能操作已核实身份的本产品进程，不因 PID 复用误杀其他程序。
- R10: 当前 CLI 命令与选项在 Windows 保持功能迁移目标，包括启动、状态及 JSON 输出、停止/重启、历史、用量、模型检查、key 管理、配置、主题、设置窗口、日志跟随、更新和卸载；更新相关分期以 R11 为准，不能假报成功。安装包提供 Windows 终端可调用的入口，不依赖 Bash、WSL 或全局 Node；日志、语言选择、路径、进程与凭据清理不得继续依赖 macOS 外部工具。GUI 退出后 CLI 的启动/重启能力也须成立。
- R11: 当前迭代优先交付本机可运行的 Windows 版本，随后验证本地可双击安装的 .exe；NSIS 是拟定安装器，打包工具及版本在实施计划中锁定。用户无需预装 Electron、Node、编译器或 WSL。当前允许未签名的本地测试包，不购买/配置签名身份，不进行公开发布；Windows 警告如实记录，不修改系统安全策略绕过。通过本地安装包覆盖升级和退回旧版验证用户数据保留；占用或中断不得导致数据丢失。卸载明确区分保留数据和清理，只移除本产品文件、快捷方式、CLI 注册和启动项。代码签名、COS/CDN 及远端版本检查/主动升级保留为后续交付，当前 Windows 更新入口说明暂未配置远端更新，不访问 macOS 包或假报已是最新版；不影响 macOS 既有发布更新链路。未来公开发行前需另行落实发布者签名与完整性验证，签名不保证 SmartScreen 零提示。
- R12: WSL2 Linux 文件系统中的源码与 Git 为唯一编辑源；Windows 本地文件系统中的调试工作副本由单向同步或导出产生，不接受反向业务编辑。两端分别使用本端 Node、项目局部 node_modules 与 Electron，同一依赖版本和锁文件；同步排除依赖、Git 元数据、构建产物、key、录音、历史和本机配置。Windows 原生助手编译、输入调试、签名、安装器构建与最终验收在 Windows 执行；WSL 可发起受控调用。WSLg/Linux GUI 检查不能替代 Windows 原生验收。
- R13: 复用当前页面布局、三套主题、深浅色、国际化和动画；只调整 Windows 标题栏/拖动区、系统字体回退、键帽、托盘图标、权限入口和 DPI。保留 key、权限/能力检查、麦克风测试、热键测试与实际听写的引导能力。自动启动及其开关在安装版生效，不把开发时 Electron 注册为用户启动应用。
